# 双栏 UI 改造:左聊天 + 右技能树(可拖拽/可折叠)

## 目标
把现在的单栏(顶部 tabs 切换技能树/仪表盘)改成 OpenChatCut 式双栏:**左侧 agent 聊天常驻,右侧技能树/仪表盘,中间可拖拽分隔线,聊天栏可折叠**。点 lesson 自动选中该节点并在聊天栏开 AI 教学。LLM 没配 key 时聊天栏显示就地配置引导。

## 架构决策
- **保持 agent 在主进程跑**(不学 OpenChatCut 把 agent 搬到 renderer)。token 流继续走 IPC,这是 LookatStudy 的安全边界(密钥不离开主进程)。OpenChatCut 走 HTTP proxy 是它的架构,我们沿用现有 IPC 流。
- **沿用 Tailwind**(OpenChatCut 用 inline-style,我们项目已锁 Tailwind v3)。
- **新增专用 IPC 通道**给 proposal/tool 事件(现在混在 `import:progress` 里丢结构)。

## 实施步骤(7 个原子改动,每个独立可验证)

### Step 1: 扩展 IPC 推送通道(shared/types.ts + preload + agent-engine)
把 proposal/tool 事件从 `import:progress` 字符串里拆出来,加专用通道:
- `IpcEvents` 加 `chat:toolCall: (name: string, args: string) => void` 和 `chat:proposal: (proposalId: string, summary: string, status: string) => void`
- preload `on()` 已支持任意 `keyof IpcEvents`,加这两个 key 到 IpcEvents 类型即可自动通
- `handleAgentChat` 改用新通道发结构化数据(`onToolCall` → `chat:toolCall`,`onProposalCreated` → `chat:proposal`)
- 保留 `chat:token`/`chat:done`/`chat:error` 不变

### Step 2: 新增 `selectedNodeId` 状态 + handleLessonClick 改造(App.tsx)
- `App` 加 `selectedNodeId` state + `selectedNode`(派生 ContentNode)
- `handleLessonClick` 现在:`markNodeAttempted` + 设 `selectedNodeId`(为聊天栏提供当前节点)
- `LessonBubble` 加"选中"视觉态(当前节点的气泡高亮)

### Step 3: 拆 App.tsx 为布局组件(为双栏做准备)
把现在的单文件 14 个组件拆成可维护的结构:
- `src/renderer/components/Sidebar.tsx` —— 左栏容器(折叠态/展开态)
- `src/renderer/components/ChatPanel.tsx` —— 聊天面板(消息列表 + 输入框 + 配置引导)
- `src/renderer/components/SkillTreePane.tsx` —— 右栏(原 `<main>` 的技能树 + 仪表盘 + view tabs)
- App.tsx 变成布局壳:管理 `chatWidth`/`chatCollapsed`/`selectedNodeId`,把 props 分发给三个子组件

### Step 4: 双栏布局壳(App.tsx 重写布局部分)
- 顶部 `Header` + `SkillPicker` 保留(横跨全宽)
- 下方 `flex` 横向:`<Sidebar>` + `<Divider>` + `<SkillTreePane>`
- `Sidebar` 宽度由 `chatWidth` state 控制(百分比,初始 38%,min 280px,max 60%)
- 折叠态:`chatCollapsed=true` 时 Sidebar 渲染成 46px 窄条(只有展开按钮)

### Step 5: 拖拽分隔线(Divider 组件)
- `src/renderer/components/Divider.tsx` —— 5px 宽拖拽条,pointer capture,拖动时改 `chatWidth`
- 点 Header 的折叠按钮 toggle `chatCollapsed`
- (简单实现:不持久化宽度,刷新重置。够用,避免引入 IndexedDB)

### Step 6: ChatPanel 聊天面板(从零搭)
状态:`messages: {role, content}[]`、`input`、`streaming`(bool)、`agentReady`
- **顶部**:当前节点标题("当前:第 X 课 · 标题")+ 折叠按钮
- **消息列表**:user 右气泡 / assistant 左气泡 + Markdown 渲染(`react-markdown` 已装)/ 流式时显示打字光标
- **工具调用条**:`api.on("chat:toolCall")` 收到时插一行"🔧 调用工具:get_node_info"
- **提议卡**:`api.on("chat:proposal")` 收到时插一张卡片(proposalId + summary + [应用]/[拒绝]按钮),点应用调 `api.applyProposal(id)`,点拒绝调 `api.rejectProposal(id)`
- **输入框**:`<textarea>` + 发送按钮;`agentReady.ready=false` 时输入框置灰显示"先配置 API key"
- **配置引导**(无 key 时):输入框区域换成 key 输入框(provider 选择 + key 输入 + 保存按钮 → `api.setSetting("glm_api_key", val)` + `api.setSetting("active_provider", "glm")`),保存后重新拉 `isAgentReady`
- 发送逻辑:`api.agentChat(selectedNodeId, input)` → 订阅 `chat:token` 追加到当前 assistant 消息 / `chat:done` 结束 streaming / `chat:error` 报错

### Step 7: ui-test 更新 + 全量验证
- ui-test 加 DOM 断言:聊天栏存在(`data-testid="chat-panel"`)、分隔线可拖拽(`data-testid="divider"`)、折叠按钮工作、无 key 时显示配置引导
- 点 lesson 后聊天栏顶部显示该节点标题(联动验证)
- 配 key 后输入框激活(就地配置验证)
- 跑 verify:core(115 断言不变)+ tsc 双端 + vite build + self-test + ui-test 全绿

## 不做的事(明确边界)
- 不把 agent 搬到 renderer(保主进程安全边界)
- 不持久化聊天栏宽度/折叠态(简单实现)
- 不做 @ 引用/chips 选择模式(OpenChatCut 的复杂特性,后续再说)
- 不改 agent-engine 的 tool 逻辑(只改事件通道)

## 验证标准
- 视觉:左聊天 + 右技能树,中间可拖拽调宽,聊天栏可折叠成窄条
- 联动:点右栏 lesson → 左栏自动切到该节点的 AI 对话
- 配置:无 key 时左栏就地填 key,填完输入框激活
- 流式:发消息 → 实时看到 token 流 + 工具调用 + 提议卡可应用/拒绝
- 测试:115 核心断言 + ui-test 新断言全绿,tsc/build 双端 clean
